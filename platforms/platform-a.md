# 平台适配层 · platform-a

> 公开仓库不出现平台商标。本文件只描述交互机制与约束。
> 平台特征：国内直聊式招聘平台；求职者须先「打招呼」才能发起对话。

## 会话机制

Tier 0 起就需要的平台知识。

| 事实 | 证据 | 对毛遂的影响 |
|---|---|---|
| 招呼语是全局固定设置，改一次影响之后所有对话 | 作者实测 | 第二条消息**不得重复**招呼语内容 |
| 招呼语仅在移动 APP 端可编辑，网页端不可编辑 | 作者实测 | 「每个岗位改一次招呼语再回头沟通」的人工路径不可行，本项目不做这条路径 |
| 点击「立即沟通」后招呼语自动发出，不可拦截 | 作者实测 | 毛遂的产物只能是**第二条消息** |
| HR 回复前可连续发送多条，自动招呼语不计入其中 | 作者实测（四五条无碍） | 第二条消息不受条数限制 |

## 内容约束

| 约束 | 来源 | 校验 |
|---|---|---|
| 第二条消息必须是纯文本 | 白皮书 §6.5 | `scripts/validate-message.py` |
| 禁止手机号、邮箱 | 白皮书 §6.5 | 同上 |
| 禁止微信 / QQ 等 IM 账号 | 白皮书 §6.5 | 同上 |
| 禁止外部链接、附件、作品集指引 | 白皮书 §6.5 | 同上 |
| 80–150 个非空白字符 | 白皮书 §6.5 工作值；折叠阈值 `待验证` | 同上 |

## 页面动作序列

**Tier 0：不适用。** agent 不访问平台，浏览、点击、粘贴、发送全部由使用者手动完成。

**Tier 1（只读）/ Tier 2（可交互）：留空，v1.1 起填写。** 动工前置条件：

1. 平台用户协议原文查证通过（白皮书 §9.3 第 1 项）
2. 岗位详情页在已登录会话中可稳定解析、不触发风控（白皮书 §9.3 第 4 项）

两项完成前，本节不得填写任何页面动作序列。

## 未验证项

聊天框折叠阈值、可连发条数上限、按账号状态是否存在差异化限制。见白皮书 §9.3。
