# 毛遂 · maosui

把「在招聘平台上开口」变成 agent 的一项技能。

招聘平台的招呼语是全局固定的一条——你设置一次，之后每点开一个对话都发同一句。这句话对每个 HR 都一样，信息量为零。毛遂不替换它（平台不允许），而是在它之后生成**第二条消息**：引用这份 JD 的具体要求，对应你简历里的真实经历。

不是群发工具，不是托管服务，不碰你的账号凭据。

## 三条硬承诺

- **不碰凭据** — 不存储、不代登录、不索取密码或 cookie
- **不做托管** — 没有毛遂的服务器
- **不群发** — 节流上限硬编码为「一个人手动也能做到的量」

## 怎么用

按你的环境分三档。**先确认自己在哪一档**，用错档会觉得项目坏了。

| 档位 | 环境 | 用法 | 校验强度 |
|---|---|---|---|
| **A** | Qoder / Claude Code 等 CLI agent | clone 仓库，技能自动发现 | 硬校验 |
| **B** | ChatGPT 等，能读文件但不能执行代码 | 同 A | 软校验（自检行） |
| **C** | DeepSeek 网页版等纯对话 | 手动粘贴 `workflow/` 文件全文 | 软校验（自检行） |

### A / B 档

1. `git clone` 本仓库
2. 把简历交给 agent，说「按 workflow/00-profile.md 建档」
3. 确认档案后写入 `.maosui/profile.md`
4. 每次贴一批 JD（建议 5–15 个），说「按 workflow/01-screen.md 筛选」
5. 圈选后说「按 workflow/02-open.md 写消息」
6. 自己到平台点「立即沟通」，把第二条消息粘进聊天框发送

### C 档（降级）

没有技能发现和本地文件能力，每次手动提供上下文：

1. 粘贴 `workflow/00-profile.md` 全文 + 简历文本 → 得到档案，自己存到本地任意文件
2. 每次筛选时粘贴 `workflow/01-screen.md` 全文 + 档案 + 一批 JD 文本
3. 圈选后粘贴 `workflow/02-open.md` 全文 → 得到消息
4. 自己去平台粘贴发送

**C 档可用，但明显更麻烦。** 这里如实说明，不假装它有 A 档的体验。

### JD 怎么提交

v1 里 agent 打不开链接，**贴链接没用**。可用形态：JD 文本（最稳）、岗位页截图（需要视觉能力）。

### 三条不要做的事

- **不要在筛选阶段要文案** —— 两步必须分开，理由见 [方案 §2.4](docs/design.md)
- **不要把多个岗位的文案合并成一段** —— 一次一个岗位，逐条给
- **不要在消息里放作品集链接** —— 留到 HR 回复之后

## 使用前提

你需要一个能执行技能的 agent harness（ChatGPT / Qoder / Claude Code / DeepSeek 等）。毛遂是能力包，不是应用，没有安装器也没有 UI。

**这是真实门槛，我们不粉饰。** 第一版服务的是本来就在用 agent 的求职者。

## 风险提示

**v1 只做 Tier 0：毛遂不接触浏览器、不访问平台，只产出文本，由你自己复制粘贴发送。** 这与你自己撰写消息在平台侧完全无差别，不涉及协议风险，也不额外增加你的账号风险——你手动操作的节奏仍由你自己负责。

未来的 Tier 1/2 会让 agent 操作浏览器，**那时才出现协议风险**：自动化访问与操作页面通常被平台用户协议禁止，即便用的是你自己的账号和浏览器。协议原文查证是 v1.1 的前置条件，查证通过前不实现。届时毛遂不声称合规、不替你承担风险，降险手段是节流、逐条人工确认、不绕风控——降低概率，不构成免责。

## 数据去向

毛遂自身不采集、不落库、不上报。

但你的简历和 JD 会进入你选择的 harness，此后由该 harness 的隐私政策约束。**任何跑在第三方模型上的方案都做不到「数据不出本地」**——声称做到的都是误导。毛遂能承诺的边界是：它自己不成为额外的数据出口。

## 不做什么

不代面试。不伪造经历——只允许重排、强调、按 JD 术语调整措辞；不允许新增未发生的经历、改动任何数字、调整时间线。
